About this demo

A2A, tunneled through Iroh to Datum Compute

Every question this agent asks and every answer it gets travels as an A2A message over an Iroh connection, brokered by Datum's Iroh relays and ending at an agent running on Datum Compute. Neither side opens an HTTP port to the internet.

The path of one request

  1. Dial a key, not an address. This agent knows one thing about the inside agent: its Iroh endpoint ID, a public key. There is no DNS name to resolve, no IP to find, and no discovery service in the loop.
  2. Meet at a Datum relay. Each side keeps a single outbound HTTPS connection (port 443) to a Datum Iroh relay. The first packets flow through the inside agent's home relay, so the connection starts immediately.
  3. Try for a direct path. While traffic is relayed, both sides attempt UDP hole-punching. If it works, traffic moves to the direct path and the relay stays as a fallback. Either way it is QUIC with TLS 1.3 end to end, and the relays only see ciphertext.
  4. Speak A2A over a stream. Each request opens a QUIC stream under the ALPN a2a-iroh/http1/0 and carries an ordinary HTTP/1.1 exchange: the Agent Card at /.well-known/agent-card.json and JSON-RPC message/send calls for skills. It is plain A2A; only the transport is unusual.
  5. Check at the gate. The inside agent learns who is calling from the cryptographic identity of the connection, checks its allowlist, applies deterministic rules, and then asks an LLM to review the request before doing any work.
  6. Answer from behind the door. The model key, Postgres and the file store live on a private Datum network next to the inside agent. None of them is exposed to the internet, and neither is the inside agent.

Why tunnel A2A this way

Some platforms, such as exe.dev, RunPod or Daytona, heavily restrict inbound and outbound HTTP. An Iroh agent needs only outbound HTTPS to a relay, so the same binary behaves the same on Fly.io, Cloud Run, exe.dev or a laptop running Podman.

The inside agent never has to be published. Datum Compute runs it with no HTTP proxy or load balancer in front of it; the only way in is to dial its key and be on its allowlist.

What crosses the tunnel

SkillWhat it does
ip.lookupGeolocation, ASN and reverse DNS for this agent's public IP, which Iroh itself discovered.
llm.completeA chat completion on a fixed model. The model key never leaves the inside agent.
data.catalog · data.queryWhat reference data exists, and read-only rows from an allowlisted Postgres table.
files.getOne small text file from an rclone-served store.
agents.syncReport this agent's metadata and receive every agent the inside agent saw in the last six hours.

What this agent does not have

No model credentials, no discovery service, and no other network peer than the inside agent. Its dashboard is its own small web server and is not part of the tunnel; everything shown on it was learned by asking the inside agent.
